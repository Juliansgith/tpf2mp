# TPF2MP 0.42.0-alpha

This carrier-support release promotes stock air and water transport from
generic-codec assumptions to explicit deterministic and exact-build evidence.
It also hardens the disposable native validation harness used to establish
that evidence. Gameplay authority remains state schema 34, checkpoint format
5, construction proposal format 7, operation format 4, economy model 10, and
native hook 0.19.0.

## Air transport

- All four stock airport families and every stock airport creation option are
  represented by portable construction fixtures, including passenger/cargo,
  terminal count, hangar, landing direction, and both landing-light eras.
- The largest modern-airport fixture carries its complete 384-node/383-edge
  private runway and taxiway graph through the production codec.
- All 29 stock aircraft resources pass the Lua and Python portable vehicle
  protocol gates.
- AIR passenger service covers capacity, speed, upkeep, allocation, fare
  revenue, queue/load conservation, and an all-peer rendezvous at every stop.
- AIR freight boards, transfers, delivers, settles revenue, and conserves
  source/destination stock without rail-only assumptions.
- Independent peer worlds with deliberately different native IDs converge
  through aircraft purchase, assignment, replacement, and sale.
- An exact Build 35924 disposable run created passenger/cargo airfields and
  airports, removed isolated cargo facilities, bought and assigned a Junkers
  F 13, and observed it move 546.935 metres.

## Water transport

- All 12 stock harbor layouts are covered: passenger/cargo, 50/100-metre
  docks, and one/two/four terminals.
- All 23 stock ship resources pass both portable vehicle protocol gates.
- WATER passenger service covers authored demand/economy and the every-harbor
  synchronization barrier.
- WATER freight uses the same conserved multi-leg cargo ledger as other
  carriers, with explicit stock and revenue regression coverage.
- Divergent-ID peer tests now cover ship purchase, assignment, replacement,
  and sale.
- An exact Build 35924 disposable run created two passenger harbors, a cargo
  harbor, and a shipyard; removed the cargo harbor; bought and assigned a
  Rigi; and observed it move 626.771 metres.

## Construction and validation hardening

- Airport and stock street-terminal option fields participate in GUI preview
  correlation, preventing an older cached shape from replaying after an option
  change.
- The one-shot validator now owns its complete standalone launcher identity so
  a stale network profile cannot leak into a disposable feature run.
- Release-only console key events tolerate the native menu window being
  destroyed between key-down and key-up, while still recording that foreground
  verification was intentionally unnecessary.
- Player-facing readiness text now accurately reports automated stock road,
  rail, tram, air, and water carrier coverage.

## Verification boundary

The complete Lua, Python, cross-language parity, launcher/updater, relay,
recovery, packaging, syntax, and architecture suite passes. The exact Build
35924 hook profile and both disposable carrier runs pass with settings restored
and no game process left running.

The new evidence is strong single-machine native proof, not a claim that every
airport/harbor option and every vehicle has completed a physical two-computer
match. The next human gate is ordinary-GUI construction/edit/removal, rival
denial, passenger and cargo operation, and pause-at-arrival synchronization for
AIR and WATER. Opaque executable mod callbacks remain outside the alpha
profile; portable data-only resources still require identical attested content
on both peers.

Both players must install `0.42.0-alpha`. Mixed versions remain unsupported.
