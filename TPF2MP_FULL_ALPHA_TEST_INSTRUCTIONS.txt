The launcher now waits for a bounded transition and retries that exact
role/session/save once. An identical already-pinned save is verified and reused;

keep the evidence and use a new session name rather than repeatedly clicking.

Identity:

  P1 = Host = player1 = Company 1
  P2 = Join = player2 = Company 2

If P2 cannot join, compare the complete support IDs and relay URLs; create a new
room rather than editing its generated game session. A wrong/expired join code,
role collision, changed content fingerprint, or missing peer is intentionally
rejected before the world becomes ready.

Use a disposable area for the deletion tests. Wait for each object to appear

P1 builds:

[ ] Normal track, one electrified/high-speed upgrade, and a crossover.
[ ] One track crossing a road.
[ ] One short bridge or tunnel.
[ ] A two-track passenger station.
[ ] A rail depot connected to the track.
[ ] A signal and a waypoint.
[ ] One plain construction such as a bench, lamp, or fence.

For every item, verify:

[ ] Only P1's competitive wallet pays for it.
[ ] Compatibility lists the exact road/track/station/object resource used.
[ ] Alpha Status returns to READY before continuing.

P2 then builds a separate short road/track/station or construction. Verify it
appears on P1 and only P2 pays.

Ownership veto:

[ ] P2 attempts to extend, electrify, edit, or bulldoze P1 private track.
[ ] The action is rejected and neither world nor wallet changes.
[ ] P1 attempts the equivalent action against P2 private infrastructure.
[ ] It is also rejected.
[ ] Connecting either player to public town roads remains allowed.

Deletion/editing regression checks:

[ ] Delete a disposable track segment connected to another track.
[ ] Delete a disposable road segment attached to a town road/house.
[ ] Place a station where it removes one native building.
[ ] Perform one modular station edit and then remove that module.
[ ] Confirm each successful result is identical on both peers.
[ ] Confirm a rejected edit does not poison later building or bulldozing.

8. TRAIN RENDEZVOUS, ESCAPE PAUSE, AND DRIFT
--------------------------------------------

[ ] Let both trains complete several station visits at Speed 3.
[ ] Leave P2 inside the Escape menu for 30-60 seconds.
[ ] Confirm the shared clock pauses both worlds after a short network delay.
[ ] Close Escape and request Speed 3 from either peer.
[ ] Confirm the session returns to Speed 3 and does not remain stuck paused.
[ ] Watch the next station visit: the leading copy may wait for its peer, but
    both copies must receive a release and continue.
[ ] Confirm two trains do not remain held forever at separate platforms.

A small mid-leg visual position lead is acceptable. Exact coordinates are not
continuously teleported. Station rounds, loads, deliveries, and the next leg's
departure are the synchronization boundary. Report any lead that grows every
round or any station hold longer than roughly one minute without a reconnect.

16. STOP IMMEDIATELY IF ANY OF THESE OCCUR
------------------------------------------

  - Alpha Status says FAULTED.
  - Geometry differs between peers after the checkpoint finishes.
  - Only one peer accepts an ordered construction/operation.
  - A wallet changes on the wrong company or changes twice.
  - Later construction stops working after one rejected action.
  - A train is held permanently with no reconnect/checkpoint pending.
  - "An error just occurred" appears in either game.
  - A launcher reports a fingerprint, save, session, or authority mismatch.

When one occurs:

1. Do not build, bulldoze, buy, assign, or settle anything else.
2. Leave both games open if they are still responsive.
3. Record the session name, P1/P2, game speed, and last action.
4. Export Research and Snapshot if the buttons still respond.
5. Capture the exact console/launcher error and a screenshot.
6. Report whether the action appeared on neither, one, or both worlds.
